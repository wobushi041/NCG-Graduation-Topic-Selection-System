> 2026-09-11 改名前为「第一组 / 第二组 / 第三组」，现已统一改为上表名称。组名是纯文本，同时存在于 `project.groupName`、`teacher_group_quota.groupName`、`topic.topicGroup` 三处；**改名必须两个表一起改**，只改一处会让教师发题报「请选择当前教师所属的选题组」。改名后需等 10 分钟缓存过期或重启 backend。

教师用固定 T 编号，学生用学号，专业负责人身份用 D 编号。专业负责人和教师身份仍为两个账号，各自修改初始密码并绑定同一邮箱后，可以使用现有身份切换功能。

教师的专业字段留空，授权组别及额度保存在 `teacher_group_quota`。教师发题必须指定获授权的组，每组独立计数；未删除的待审、打回及已发布题目均占用额度，删除题目后恢复容量。修改题目的组别也会校验目标组额度。`user.topicAmount` 保留为总剩余额度，调整组额度时须同时重算为各组总上限减去当前未删除题目总数。

专业负责人的专业决定其审核组，同组负责人任一人可以审核，实际审核人记录在题目中。该改动针对题目列表和审核权限；原有按系部统计、账号管理等范围未改成按组。

> 2026-09-11 界面称谓统一：原「系主任 / 主任」全部改为「专业负责人」（8 位负责人 ↔ 8 个专业一一对应）。**只改了展示层**，代码标识仍为 `userRole=2` / `UserRoleEnum.DIRECTOR` / `dept` / `canAccessDept`。审核隔离粒度也**仍是选题组、不是专业**——同组的 2-3 位负责人依然可以互审对方的题。若将来要改成「每位负责人只管本专业的题」，需改后端判定逻辑，而非文案。

## 后续名单更新

固定账号对照和初始凭据保存在本机 `.workbuddy/import-2023-20260911/`（已被 Git 忽略），不要上传到公开仓库或把全体密码清单群发。

新增人员续编账号，已有人员保留账号、密码及选题记录。不能按新名单的行号重新编号；重名应核实后再匹配。删除名单中的人员需单独确认停用，不能直接删除关联记录。

现有 CSV 导入遇到已有账号会跳过，不会更新资料，也不会配置教师分组额度。名单更新需先生成新增与变更清单，再在备份后按账号更新；额度下调不得小于该组当前未删除的题目数。现有后台总额度表单不能单独调整组额度，分组额度通过维护导入处理。

首次导入脚本有空库保护，不能重复运行。部署前数据库备份及旧镜像保存在服务器 release 目录和 `before-groups-20260911` 镜像标签中；回滚数据前必须检查导入后是否已有新操作。

原名单额度合计为 1227。若每题仅接收 1 名学生，与 1323 名学生相比少 96 个名额，后续需由负责老师确认额度或题目容量。
