> 对外发送请使用 `deploy/给老师的材料/` 下的《给院系的说明》和 CSV 模板，不要直接发送本文档。

系统地址：https://topic.lqlab.cn

请协助提供以下 **3 份表格**。所有表格请用本目录下的 CSV 模板填写，**不要改动列顺序**，不要新增或删除列。

## 01 院系专业填报表

列：`系部名称,专业名称,选题组名称`

| 列 | 填写说明 |
| --- | --- |
| 系部名称 | 行政归属，如「工学院」。**全系统唯一，改名会导致历史数据失配** |
| 专业名称 | 如「计算机科学与技术」，必须挂在某个系部下。**专业名全系统唯一，不能重复** |
| 选题组名称 | **多个专业填同一个组名 = 这几个专业合成一个选题池**。见下方说明 |

### 选题组是干什么的

系统里有三层结构，容易混淆，这里一次讲清：

| 层级 | 例子 | 作用 |
| --- | --- | --- |
| 系部 | 工学院 | 行政归属，管跨系开关 |
| 专业 | 计算机科学与技术 | 学生/教师的所属专业 |
| **选题组** | 计算机类 | **挂在专业上的一个标签**，决定学生能选哪些题 |

**关键规则：选题组是"多对一"的。** 2023 级 8 个专业分成 3 组，就让同组的专业填**同一个组名**（以下为 2026-09-11 线上实际配置）：

```
系部名称,专业名称,选题组名称
工学院,计算机科学与技术,计算机类
工学院,软件工程,计算机类
工学院,数据科学与大数据技术,数据智能类
工学院,数据科学与大数据技术（中外）,数据智能类
工学院,智能科学与技术,数据智能类
工学院,电气工程及其自动化,电子电气类
工学院,电子信息科学与技术,电子电气类
工学院,通信工程,电子电气类
```

这样：计科和软件工程的学生能互相选题目，但不能选另外两组的题。

> ❌ 错误填法：给每个专业起一个独立组名（如「计算机科学与技术组」「软件工程组」）——这样等于没分组，8 个组各选各的。

### 组名是自由文本，但必须"同组同名"

（2026-09-11 更正：旧版本这里写的"下拉只能选第一组/第二组/第三组"**已经过时**。）

- 组名**不是枚举**，是自由文本，存三处：`project.groupName`、`teacher_group_quota.groupName`、`topic.topicGroup`。
- 线上已统一配置为 **计算机类 / 数据智能类 / 电子电气类**（原名「第一组 / 第二组 / 第三组」已废弃）。
- 改组名**必须两张表一起改**（`project` + `teacher_group_quota`），只改一处会让教师发题时报「请选择当前教师所属的选题组」。
- 教师发布题目时的「适用选题组」是**必选项**，下拉选项由后端 `GET /user/teacher/groups` 动态返回，**只列出该教师在 `teacher_group_quota` 里有额度的组**（显示为「计算机类（剩余 5 / 8）」）。教师没有配额的组不会出现。
- ⚠️ 要**通知到每一位出题教师**：发题时必须在「适用选题组」里选中组。该字段为空会被后端拒绝，分组配置也就白做了。

### 还有一个必须确认的点：这些专业分属几个系？

- 如果 **全部专业同属一个系**（2023 级的实际情况：8 个专业都在工学院）→ 分组按上表配即可，跨系开关保持关闭。
- 如果 **分属多个系**，且同一组里有跨系的专业 → 必须额外开启跨系开关，否则同组不同系的学生互相选不到题。

## 02 教师名单

列：`工号,姓名,系部,专业,最大出题数量,临时密码`

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 工号 | ✅ | 登录账号，全系统唯一 |
| 姓名 | ✅ | 真实姓名，学生选题时显示 |
| 系部 | ✅ | **必须与 01 表的系部名称完全一致** |
| 专业 | 建议填 | 同样要与 01 表一致，留空也可以 |
| 最大出题数量 | ✅ | 0–20 的整数，该教师最多能发几个题 |
| 临时密码 | 可留空 | **建议整列留空，由技术人员统一生成** |

示例：

```
工号,姓名,系部,专业,最大出题数量,临时密码
2021001,张老师,工学院,计算机科学与技术,8,
2021002,李老师,工学院,软件工程,6,
```

> 注意：教师账号的专业字段即使留空也不影响发题（发题校验的是 `teacher_group_quota`），但填上更完整。

## 04 专业负责人名单（单独提供）

列：`工号,姓名,专业`

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 工号 | ✅ | 登录账号，全系统唯一，一般用 D 编号 |
| 姓名 | ✅ | 真实姓名 |
| 专业 | ✅ | **每个专业 1 位**，账号由后台单独开通 |

专业负责人负责审核题目、查看本系选题情况、导出统计结果。**不能由教师账号兼任**——系统里负责人和教师是两个独立账号（靠同名 + 同系 + 同邮箱做一键切换关联）。

> 审核隔离粒度是**选题组**，不是专业：同组的 2-3 位负责人可以互审对方的题。

## 三个最容易出错的地方（请务必注意）

1. **系部、专业名称必须各表完全一致**
   系统靠文字精确匹配，`工学院` 和 `工学院 `（尾部空格）会被当成两个系部。填之前先定好标准名称。

2. **选题组名称要"同组同名"**
   同一组的几个专业，组名必须**一字不差**（含空格）。写成 `计算机类` 和 `计算机类 `（尾部多空格）会被当成两个组。

3. **文件必须存成 CSV UTF-8 编码**
   Excel 直接「另存为 CSV」默认 GBK，导入后中文会变乱码。
   正确做法：Excel「文件 → 另存为 → 其他格式 → CSV UTF-8（逗号分隔）」。
   更稳妥：填完直接发 .xlsx 原文件过来，由技术人员转码。

4. **临时密码整列留空最省事**
   系统要求每个账号的临时密码至少 12 位且**互不相同**，人工编很容易重复导致整表导入失败。留空由技术人员批量生成即可。

## 还需要一并确认的 6 项规则

这些是系统开关，需要老师拍板：

1. **每位学生最多能预选几个题目？**
2. **每位教师出题上限是否统一？**（也可在教师名单里逐个指定）
3. **选题时间窗**：预选开放时间、正式确认开放时间（具体日期和时刻）
4. **是否允许跨系选题？** 允许的话，各系允许选哪些系？（若同一选题组内存在跨系专业，此项必须开启）
5. **专业负责人名单**：每个专业 1 位，工号 + 姓名 + 专业（账号由管理员在后台单独建，负责审核题目）
6. **哪个专业对应哪个选题组**（需与 01 表一致，线上现为 计算机类 / 数据智能类 / 电子电气类）

> 另外还有一项业务选择：**选题模式**（学生选老师 / 老师选学生），由系统开关「单选模式切换」控制。
